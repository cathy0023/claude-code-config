## ④ RFC 全家桶（5 个，业务深度定制）

> 完整 RFC 驱动开发流水线，每个 Skill 职责单一，可独立触发也可由 `rfc-driven-dev` 串行编排。

| Skill | 流水线位置 | 能力 |
|-------|----------|------|
| `rfc-brainstorm` | **第 0 步**：写 inbox 之前 | 通过一次一个问题厘清需求边界，产出结构化 inbox 文档 |
| `rfc-author` | 第 1 步：inbox → draft | 从 `docs/rfcs/inbox/` 原始文档生成规范 RFC 到 `docs/rfcs/draft/`（含模板、命名规范、序号管理） |
| `mgv-rfc-approve` | 第 2 步：draft → approved | **5 维度完整性检查** + 状态流转（Draft → Approved），通过后 `git mv` 到 `approved/` 并更新索引 |
| `rfc-driven-dev` | **总编排器** | 11 阶段完整流水线：调研→RFC 生成→评审→审批→Plan→实现→Review→修复→归档→交付 |
| `rfc-init` | 项目初始化（一次性） | 在项目中创建 `docs/rfcs/` 目录结构和 README 索引 |

> **mgv-** 前缀是 MGV 业务深度定制的硬证据。
